## 1. Edits to Parts 1–2 (ideas and design)

**Replace the ground rules on page 1.** Rule 2 used to say "every model is trained on your own recorded RSSI, no external dataset". New wording:

- Every model is trained on RSSI that **you** produced: either recorded in the room (real) or generated by **your own** calibrated NS2 testbed (synthetic). No external dataset, no pretrained model, no prediction API.
- Every row carries an `origin` tag (`real` or `sim`). Simulated windows are used for training, ablation and pipeline testing only. **They never appear in any test set**, and headline accuracy claims rest on real sessions alone.
- All other ground rules (illustrative numbers marked, no fabricated results, camera-free, local-only) are unchanged.

**Add as section 1.13 — Why simulate at all, and what NS2 can and cannot teach.**

A real room gives you a handful of sessions, one layout and one set of boards. A simulator gives you hundreds of seeded, perfectly labelled runs, any receiver layout, and controlled drift. The price is that the simulator is a *model*: NS2's Shadowing channel draws a fresh Gaussian dB offset for every packet around a log-distance mean. Real RSSI has multipath, temporal correlation (a fade lasts as long as the geometry holds) and quantisation to 1 dB; NS2 has none of these unless you add them.

So NS2 is good for: repeatable experiments, design-space sweeps, pre-training when real sessions are few, and the 802.11 network behaviour (collisions, delivery, delay). It is not evidence about what the real room does. That asymmetry is the reason for the origin tag and for objectives O9 and O11, which measure how far to trust it.

A body in the simulation exists only because **you** wrote it into the propagation model (BodyShadow, Part 26.8). Its numbers are fitted from your pilot data, so the simulation can only be as good as that fit.

## 4. NEW Part 26 — The NS2 Simulation Testbed (Hero 2)

### 26.1 What NS2 is, in plain words

NS2 is a *discrete-event* simulator. Nothing runs in real time. You describe nodes, their radios, their positions and what traffic they send; NS2 keeps a sorted list of future events ("node 0 sends a packet at t = 3.0 s", "that packet reaches node 1 at t = 3.0004 s") and processes them in order, as fast as the computer can. At each event the simulator calls C++ code that models the radio, and writes a line into a trace file.

Two languages work together. **C++** holds the fast inner models (the 802.11 MAC, the `WirelessPhy` receiver, the propagation models). **OTcl/Tcl** is the scripting layer where you build the scenario: create the scheduler, create nodes, set parameters, schedule `$ns at <time> "..."` actions. Rule of thumb for you: *scenarios are Tcl; the RSSI trace and the body model are C++*. Changing C++ means recompiling NS2 (`make` in `ns-2.35`).

Each wireless node is a stack: application (a UDP/CBR agent) → routing → link layer → MAC (`Mac/802_11`) → physical layer (`Phy/WirelessPhy`) → shared `Channel/WirelessChannel`. When a packet is transmitted, the channel hands it to every other node's physical layer, and each physical layer asks the **propagation model** how much power would arrive there. That call is where RSSI lives, and it is exactly where we hook in.

### 26.2 The channel model you will use

NS2 offers free space (Friis), two-ray ground and **Shadowing**. Two-ray is for outdoor distances and is wrong for a 5 m room, so use Shadowing. Its received power in dB, relative to a reference distance d₀, is:

```latex
P_r(d)\,[\mathrm{dBm}] = P_r(d_0)\,[\mathrm{dBm}] - 10\,\beta\,\log_{10}\!\left(\frac{d}{d_0}\right) + X_\sigma,\qquad X_\sigma \sim \mathcal{N}(0,\sigma^2)
```

where β is the path-loss exponent (`pathlossExp_`), σ is the shadowing deviation in dB (`std_db_`), d₀ is `dist0_`, and P\_r(d₀) comes from the free-space Friis formula at d₀. Three parameters (β, σ and the effective transmit power that sets the level at d₀) describe your room's *empty* behaviour. BodyShadow (26.8) adds the person.

**Worked example \[illustrative\].** At 2.437 GHz the wavelength is 0.123 m. With a 0.1 W transmitter, unit antenna gains and no system loss, Friis gives 9.6 µW (−20.2 dBm) at d₀ = 1 m. With β = 2.7 at 4 m: −20.2 − 27·log₁₀(4) = −36.5 dBm, then add a random dB offset with spread σ. A real ESP32 link at 4 m typically reads much lower than that, because real boards have antenna loss, a lower effective output and furniture in the way. This is not a bug: it is why calibration (26.11) fits the level at d₀ as well, using NS2's `Pt_` or `L_` as the knob.

### 26.3 Facts about NS2 that will bite you (read before writing any scenario)

1. **Default radio thresholds are for 250 m outdoors.** `RXThresh_` defaults to 3.652e-10 W (about −64 dBm). Left alone, every packet weaker than −64 dBm is *dropped*, so your simulated room would lose most packets. Set `RXThresh_` to about 1e-12 W (−90 dBm), the real receiver's practical floor, and `CSThresh_` just below it (e.g. 7.9e-13 W). Also set `freq_` to 2.437e9 (channel 6) and `Pt_`.
2. **There are no AP beacons in NS2's ad-hoc 802.11.** Use UDP/CBR packets at 102.4 ms as the beacon proxy (proposal 8.1). Disable RTS/CTS for them (`Mac/802_11 set RTSThreshold_ 3000`) so each sample is one clean data frame.
3. **Shadowing is drawn independently per packet.** Real fades last as long as the geometry stays put, so real RSSI is correlated in time; NS2's is not. Your simulated variance and your simulated lag-1 autocorrelation will differ from real data. Measure both (26.11); if the gap matters, add a slowly varying term in BodyShadow (an AR(1) process per link). This is a real, documented limitation, not something to hide.
4. **Routing traffic pollutes the trace.** DSDV or AODV send their own packets. Either use a routing agent that does not (NOAH) or filter on packet type in the patch (log only `PT_CBR`).
5. **Units.** NS2 works in watts. Convert once, in the patch: `rssi_dbm = 10 * log10(Pr * 1000)`.
6. **Seeds.** Set the shadowing seed explicitly per run (`seed_` on the propagation model, plus the global RNG seed), otherwise two "different" runs can be identical or non-repeatable. Record the seed in `meta.json`.

The parameter and class names above are from the NS2 2.35 manual and source layout as I know them; confirm each against your own `ns-2.35/mobile/shadowing.cc`, `mac/wireless-phy.cc` and `tcl/lib/ns-default.tcl` before relying on it.

### 26.4 How the real system maps onto NS2

| Real system | NS2 object | Notes |
| --- | --- | --- |
| ESP32 TX (SoftAP) | Static node 0 with a `UDP` agent + `CBR` source, interval 0.1024 s | One flow per receiver, offset by a few ms so frames do not collide |
| ESP32 R1, R2 (sniffers) | Static nodes 1, 2 with `Null` agents | Their `WirelessPhy::sendUp` is where RSSI is logged |

### 26.5 The NS2 workflow, end to end

### 26.6 Scenarios S1–S5 and the generator

The key idea: **the simulation reuses the real protocol files.** `gen_scenarios.py` reads the same `state_run.yaml` and `drill.yaml` you use for real recordings and compiles them into Tcl movement commands plus an `events.csv`. Labels therefore come from the same event vocabulary, and `labeling.py` runs unchanged on simulated runs.

| ID | Real counterpart | Protocol | People (NS2 nodes) | Motion | Labels |
| --- | --- | --- | --- | --- | --- |
| S1 Empty | Empty blocks | `state_run` with 0 people | none inside | — | Empty |
| S2 One person | Run A | `state_run`, 1 person | 1 node, walks to a seat at the door-cross, then stays | seated: no `setdest` | Empty, Occupied, Transition |
| S3 Multiple people | Runs C, D | `state_run`, 3 people, activity `moving` | 3 nodes | random waypoints, 0.4–1.2 m/s | same |
| S4 Enter/leave | Run E | `drill` | 1 node | outside → door → inside → door → outside, 15 times | same, many Transition |
| S5 Near/far | optional phone runs | `nearfar` protocol (to write) | the person node *is* the transmitter | stands in the Near zone or Far zone | Near, Far (separate dataset and model) |

One run = one (scenario, seed). With 10 seeds × 5 scenarios you get 50 sessions in roughly 50 CPU-minutes. Every run records its seed and the parameter block in `meta.json`.

```python
# src/occ/sim/gen_scenarios.py  (core; adjust coordinates to YOUR room sketch)
import csv, json, math, random, sys, yaml
from pathlib import Path
from occ.config import load_config

SPEED, ROOM = 1.0, (6.0, 4.5)                      # m/s, (L, W) from meta.json
DOOR, OUTSIDE = (0.2, 2.25), (-2.0, 2.25)          # placeholders
SEATS = [(4.0, 3.2), (2.2, 1.2), (3.5, 1.0)]       # desk, table, spare
TX, R1, R2 = (0.3, 0.3), (5.7, 0.4), (3.0, 4.2)    # same numbers as meta.json

def flatten(steps):
    for s in steps:
        if s["type"] == "repeat":
            for _ in range(s["count"]): yield from flatten(s["steps"])
        else:
            yield s

def compile_run(steps, rng):
    seq, t = list(flatten(steps)), 0.0
    events, moves = [], []          # events: rows for events.csv; moves: (time, person, x, y, speed)
    pos, inside = {}, []
    def go(t0, p, to):              # schedule a walk; return travel time
        d = math.dist(pos.get(p, OUTSIDE), to); pos[p] = to
        moves.append((t0, p, to[0], to[1], SPEED)); return d / SPEED
    for k, s in enumerate(seq):
        if s["type"] == "state":
            events.append((t, "state_start", s["label"], s.get("person_count", ""),
                           s.get("activity", ""), s.get("position", "")))
            if s.get("activity") == "moving":                  # S3: wander inside the room
                for p in inside:
                    tt = t + 6.0
                    while tt < t + s["seconds"] - 6:
                        to = (rng.uniform(.6, ROOM[0] - .6), rng.uniform(.6, ROOM[1] - .6))
                        tt += go(tt, p, to) + rng.uniform(1, 4)
            t += s["seconds"]
        else:                                                   # a door crossing at time t
            events.append((t, f"door_cross_{s['direction']}", "", "", "", ""))
            if s["direction"] == "in":
                nxt = next(x for x in seq[k + 1:] if x["type"] == "state")
                inside = list(range(int(nxt.get("person_count", 1))))
                for i, p in enumerate(inside):
                    pos[p] = OUTSIDE                              # arrive at the door exactly at t
                    go(t - math.dist(OUTSIDE, DOOR) / SPEED - 0.4 * i, p, DOOR)
                    go(t + 0.4 * i, p, SEATS[i % len(SEATS)])    # walk on to the seat
            else:
                for i, p in enumerate(inside):
                    go(t - math.dist(pos[p], DOOR) / SPEED - 0.4 * i, p, DOOR)
                    go(t + 0.4 * i, p, OUTSIDE)
                inside = []
    return events, sorted(moves), t, len({m[1] for m in moves})

def write_run(scn, seed, cfg, out=Path("ns2/tcl")):
    rng = random.Random(seed)
    steps = yaml.safe_load(open(f"configs/protocols/{scn['protocol']}.yaml"))["steps"]
    ev, moves, dur, npers = compile_run(steps, rng)
    c, b, run = cfg["sim"]["channel"], cfg["sim"]["body"], f"SIM_{scn['id']}_seed{seed:02d}"
    tcl = open("ns2/tcl/room_base.tcl").read()
    for k, v in {"@RUN@": run, "@SEED@": seed, "@NN@": 3 + npers, "@STOP@": dur,
                 "@X@": ROOM[0], "@Y@": ROOM[1], "@BETA@": c["pathloss_exp"], "@STD@": c["shadow_std_db"],
                 "@PT@": c["tx_power_w"], "@LOSS@": b["loss_db"], "@XSTD@": b["extra_std_db"],
                 "@FRES@": b["fresnel_scale"], "@INT@": cfg["sim"]["tx_interval_s"]}.items():
        tcl = tcl.replace(k, str(v))
    tcl += "\n" + "\n".join(f'$ns at {t:.3f} "$n({3+p}) setdest {x:.2f} {y:.2f} {sp:.2f}"'
                          for t, p, x, y, sp in moves)
    for p in range(npers):                                  # people start outside the room
        tcl = tcl.replace("# PERSON_INIT", f"$n({3+p}) set X_ {OUTSIDE[0]}; $n({3+p}) set Y_ {OUTSIDE[1]}\n# PERSON_INIT")
    Path(out, run + ".tcl").write_text(tcl)
    with open(f"ns2/out/{run}.events.csv", "w", newline="") as f:   # same columns as the real events.csv
        w = csv.writer(f); w.writerow(["t_host", "event_type", "value", "person_count", "activity", "position"])
        w.writerow([0.0, "run_start"] + [""] * 4)
        for r in ev: w.writerow(r)
        w.writerow([dur, "run_end"] + [""] * 4)
    return run
```

Two things to notice. `go()` returns the travel time so the person is *at the door* when the crossing event is logged; the walk to the seat then happens inside the Occupied block, as it does in real runs. And the `0.4 * i` stagger keeps multiple people from entering as one blob. All coordinates above are placeholders: copy yours from the sketch you made in Part 3.9, because the NS2 positions must equal the real ones (proposal Fig. 4).

### 26.8 BodyShadow: the human-body extension (C++)

**Idea.** A person only matters to a link if they stand near the straight line from transmitter to receiver. Model that line, take the person's perpendicular distance d⊥ to it, and add a loss that fades with distance relative to the first Fresnel-zone radius:

```latex
r_F = \sqrt{\frac{\lambda\, d_1 d_2}{d_1 + d_2}},\qquad
w = s\, r_F + r_{body},\qquad
g = \exp\!\left(-\left(\frac{d_\perp}{w}\right)^{2}\right)
```

```latex
P_r^{\mathrm{body}} = P_r^{\mathrm{shadow}} - L_{body}\, g \;+\; \mathcal{N}\!\left(0,\, (\sigma_{body}\, g)^{2}\right)
```

Here d₁, d₂ are the distances from the person's projection to the transmitter and receiver, λ ≈ 0.123 m, s is `fresnel_scale_`, r\_body ≈ 0.2 m is half a body width, L\_body is `loss_db_` and σ\_body is `extra_std_db_`. With several people, apply the formula per person and add the losses in dB. A standing person on the line (g ≈ 1) gives the full loss; 1 m off the line, g is small. Motion needs no extra code: as a person moves, g changes from packet to packet, so the received power fluctuates, and that is the "moving occupant raises the variance" effect of Part 1.4. L\_body, σ\_body and s are the three numbers calibration fits (26.11).

```cpp
// ns2/patches/bodyshadow.h  (add mobile/bodyshadow.cc + .o to Makefile OBJ_CC)
#include <vector>
#include "shadowing.h"
class MobileNode;
class BodyShadow : public Shadowing {
 public:
  BodyShadow();
  virtual double Pr(PacketStamp *tx, PacketStamp *rx, WirelessPhy *ifp);
  virtual int command(int argc, const char*const* argv);
 protected:
  std::vector<MobileNode*> people_;
  double loss_db_, extra_std_db_, fresnel_scale_, body_radius_;
  RNG *rv_;
};
```

```cpp
// ns2/patches/bodyshadow.cc
#include <math.h>
#include "bodyshadow.h"
#include "mobilenode.h"
#include "wireless-phy.h"

static class BodyShadowClass : public TclClass {
 public: BodyShadowClass() : TclClass("Propagation/BodyShadow") {}
  TclObject* create(int, const char*const*) { return new BodyShadow; }
} class_bodyshadow;

BodyShadow::BodyShadow() : Shadowing() {
  bind("loss_db_", &loss_db_); bind("extra_std_db_", &extra_std_db_);
  bind("fresnel_scale_", &fresnel_scale_); body_radius_ = 0.2;
  rv_ = new RNG; rv_->set_seed(RNG::RAW_SEED_SOURCE, (int)seed_ + 1000);
}
int BodyShadow::command(int argc, const char*const* argv) {
  if (argc == 3 && strcmp(argv[1], "person") == 0) {        // $prop person $node
    people_.push_back((MobileNode*) TclObject::lookup(argv[2])); return TCL_OK; }
  return Shadowing::command(argc, argv);
}
double BodyShadow::Pr(PacketStamp *t, PacketStamp *r, WirelessPhy *ifp) {
  double pr = Shadowing::Pr(t, r, ifp);                      // path loss + Gaussian shadowing
  MobileNode *tn = (MobileNode*) t->getNode(), *rn = (MobileNode*) r->getNode();
  tn->update_position(); rn->update_position();
  double ax = tn->X(), ay = tn->Y(), bx = rn->X(), by = rn->Y();
  double L = sqrt((bx-ax)*(bx-ax) + (by-ay)*(by-ay)), lambda = 3e8 / ifp->getFreq();
  double extra_db = 0, var_db2 = 0;
  for (size_t i = 0; i < people_.size(); i++) {
    MobileNode *p = people_[i]; p->update_position();
    double s = ((p->X()-ax)*(bx-ax) + (p->Y()-ay)*(by-ay)) / (L*L);   // position along the link, 0..1
    if (s <= 0 || s >= 1) continue;                                    // beside or behind an end
    double dperp = fabs((p->X()-ax)*(by-ay) - (p->Y()-ay)*(bx-ax)) / L;
    double d1 = s*L, d2 = (1-s)*L, rF = sqrt(lambda*d1*d2/(d1+d2));
    double w = fresnel_scale_*rF + body_radius_, g = exp(-(dperp/w)*(dperp/w));
    extra_db += loss_db_ * g; var_db2 += extra_std_db_*extra_std_db_*g*g;
  }
  double db = -extra_db + rv_->normal(0.0, sqrt(var_db2));
  return pr * pow(10.0, db / 10.0);
}
```

**Why the beacon proxy interval is 0.1024 s.** On the 10 Hz grid this gives 1.024 slots per sample, so about 1 slot in 42 (2.3%) is empty, almost exactly the real gap rate. Gap filling, windowing and features then behave on simulated data as they do on real data, with no artificial dropout code.

### 26.11 Sim-to-real calibration (objective O9)

**Goal.** Choose NS2 parameters so that simulated empty-room and occupied-room RSSI look like measured RSSI, and *measure* how close they get. Calibrate on **D0 (and pilot) only**; judge on D1–D3.

**Step 1 — channel from `D0_dist`.** For each distance d\_k compute the mean m\_k and standard deviation s\_k of the raw RSSI. Fit a straight line of m\_k against log₁₀(d\_k):

```latex
m_k = A - 10\,\beta\,\log_{10}(d_k)
```

The slope gives β; the intercept A is the level at d₀ = 1 m. The shadowing deviation is the typical s\_k with the 1 dB quantisation noise removed: σ ≈ √(s² − 1/12), because the simulator is quantised too. NS2's *effective transmit power* that reproduces A follows from Friis at d₀:

```latex
P_t\,[\mathrm{W}] = 10^{A/10}\cdot 10^{-3}\cdot\frac{(4\pi d_0)^2}{\lambda^{2}}
```

(unit gains, L = 1). Also record the lag-1 autocorrelation of the real empty-room signal; NS2 will produce about zero, and you should report that mismatch.

**Step 2 — body from `D0_body`.** For each person position, ΔL(d⊥) = mean(empty) − mean(person), with d⊥ the perpendicular distance from the link. Fit ΔL = L\_body · exp(−(d⊥/w)²) by least squares. L\_body is the on-line loss; the width w gives the Fresnel scale s = (w − r\_body)/r\_F. Take σ\_body from the extra spread when the person stands on the line: √(max(0, s\_on² − s\_empty²)).

```python
# scripts/calibrate_ns2.py  (core)
import numpy as np
from scipy.optimize import curve_fit
def fit_channel(dist_m, mean_dbm, std_dbm):
    slope, A = np.polyfit(np.log10(dist_m), mean_dbm, 1)
    beta = -slope / 10.0
    sigma = np.sqrt(max(np.mean(np.square(std_dbm)) - 1/12, 0.0))
    return beta, A, sigma
def fit_body(dperp, delta_db, r_body=0.2, rF_mid=0.35):
    f = lambda d, L, w: L * np.exp(-(d / w) ** 2)
    (L, w), _ = curve_fit(f, dperp, delta_db, p0=[delta_db.max(), 0.5], bounds=([0, 0.05], [30, 3]))
    return L, (w - r_body) / rF_mid              # loss_db, fresnel_scale
```

Write the results back into the `sim.channel` and `sim.body` blocks of the config (keep the old block as `*_default` for the "before" arm), regenerate the batch, and tag the run folders with the parameter set.

**Step 3 — fidelity metrics.** Compare distributions with the two statistics the proposal names:

- **Kolmogorov–Smirnov statistic** D = max |F\_sim(x) − F\_real(x)|, between 0 (identical) and 1. Report D only. The p-value is not meaningful here, because 50%-overlapping windows are not independent samples.
- **Wasserstein-1 distance**, the average amount you must shift sim values to match real ones, in dB. Easy to explain: "0.8 dB" means the two distributions are 0.8 dB apart on average.

```python
# src/occ/sim/fidelity.py
import pandas as pd
from scipy.stats import ks_2samp, wasserstein_distance
def fidelity_table(real, sim, feats=("R1_mean", "R2_mean", "R1_std", "R2_std"),
                   by=("scenario_family", "label")):
    rows = []
    for key, g_real in real.groupby(list(by)):
        g_sim = sim[(sim[list(by)] == pd.Series(key, index=list(by))).all(axis=1)]
        if len(g_sim) < 20: continue
        for f in feats:
            rows.append({**dict(zip(by, key)), "feature": f, "n_real": len(g_real), "n_sim": len(g_sim),
                         "KS": ks_2samp(g_real[f], g_sim[f]).statistic,
                         "W1_dB": wasserstein_distance(g_real[f], g_sim[f])})
    return pd.DataFrame(rows)
```

### 26.12 The NS2 network study (objective O10)

**What is being studied, and why it is separate from the room.** The MVP collects RSSI by USB, so the Wi-Fi network never carries the data. The NS2 study asks the scale-up question: *if each receiver reported its samples over 802.11 to a gateway, how many receivers, devices and what sampling rate can the network sustain before samples are lost or late?* Say this explicitly in the report; do not present the NS2 numbers as properties of the USB prototype.

**Model.** N receiver nodes each send one UDP report per sample (about 40 bytes of payload) to a gateway node at rate f; D extra "device" nodes generate background CBR traffic (e.g. 50 packets/s, 512 bytes) on the same channel. Sweep the three factors of the config block `netstudy`, run 5 seeds per setting, and compute from the standard NS2 trace:

- **Packet delivery ratio** = packets received at the gateway ÷ packets sent by receivers.
- **Delay** = receive time − send time for the same packet id; report mean and 95th percentile.
- **Throughput** = received bytes ÷ run time.
- **Gap length** = number of consecutive missing reports per receiver; its 95th percentile tells you whether `max_gap = 5` slots in Part 8.2 is adequate.

```python
# src/occ/sim/netstudy.py  (standard old-format NS2 wireless trace)
import pandas as pd
def read_tr(path):
    rows = []
    for line in open(path):
        p = line.split()
        if len(p) > 8 and p[3] == "AGT" and p[6] == "cbr":      # app-layer send/receive only
            rows.append((p[0], float(p[1]), int(p[2].strip("_")), int(p[5]), int(p[7])))
    return pd.DataFrame(rows, columns=["ev", "t", "node", "uid", "size"])
def metrics(df, gateway):
    s, r = df[df.ev == "s"].set_index("uid"), df[(df.ev == "r") & (df.node == gateway)].set_index("uid")
    s = s[s.node != gateway]
    j = s.join(r, lsuffix="_s", rsuffix="_r", how="left")
    delay = (j.t_r - j.t_s).dropna()
    return {"pdr": j.t_r.notna().mean(), "delay_mean": delay.mean(), "delay_p95": delay.quantile(.95),
            "throughput_Bps": r["size"].sum() / (df.t.max() - df.t.min())}
```

Column positions in the trace (`p[3]` layer, `p[5]` packet id, `p[6]` type, `p[7]` size) hold for the standard wireless trace format; print one line of your own `.tr` and adjust if your NS2 build writes the newer format.

**Back-of-envelope check before you run it \[illustrative\].** At the 1 Mb/s basic rate, one 100-byte report costs about 2 ms of air time once you add the 192 µs preamble, MAC headers, the ACK and average back-off. That caps the whole channel at roughly 450–500 reports per second. So 8 receivers at 50 Hz (400/s) should already be near saturation, and 8 at 100 Hz (800/s) cannot fit at all. If NS2 shows delivery staying near 100% there, something is mis-set (rate, packet size or the RTS threshold); if it shows the knee in the right region, your setup is plausible.

**How it feeds the latency budget.** In Part 16.1 add the network term: pipeline latency = guard + processing + (collection-network delay) + DB commit + dashboard polling. Take the delay p95 at the sampling rate and receiver count you actually use. The study then answers the proposal's question: *what is the largest sampling rate for which delivery stays above, say, 95% and delay stays far below the 2 s target?* Experiment **E15**. The 95% threshold is a choice you must state; it is not in the proposal.

### 26.14 Simulation-assisted learning (objective O11)

**The question.** Does adding NS2-generated windows to training improve results on **held-out real sessions**, and when? Four regimes, each tested on the same real held-out runs:

| Regime | Training data | How it is trained |
| --- | --- | --- |
| (a) real-only | n real sessions | the normal pipeline |
| (b) sim-only | all simulated sessions | the normal pipeline, zero real data |
| (c) pre-train, fine-tune | sim first, then n real sessions | continue training where the algorithm allows it (below) |
| (d) mixed | n real + simulated, with sim weight w | one fit; sim rows carry weight w ∈ {0.1, 0.3, 1.0} |

**What "fine-tune" can mean for each of the five models.** Not every model has a natural way to continue training, and inventing one would make the comparison unfair:

- **Random Forest:** `warm_start=True`. Fit 150 trees on sim, raise `n_estimators` to 300, fit again on real: the new 150 trees see only real data; the old ones stay. The result is an ensemble of sim-trained and real-trained trees.
- **Logistic regression:** `warm_start=True` with lbfgs starts the second fit from the first fit's coefficients; with the scaler fitted on real data (refit it, since sim and real level statistics differ). The code below implements the Random Forest case only; add the logistic-regression branch in \`regimes\` the same way.
- **Threshold, KNN, SVM:** no incremental training. Report regime (c) as "not applicable" for them and compare (a), (b), (d) only. Do not silently substitute another procedure.

Random Forest is the primary model, so regime (c) is meaningful for the headline result.

**Domain shift and relative features.** Even a well-calibrated simulator differs in absolute level (a moved board shifts real dBm by several dB). Reduce this for both origins with the baseline-relative features of Part 15: subtract each run's install-time baseline (median of its first 20 Empty windows) from `mean`, `min`, `max`. Run the study once with absolute and once with relative features; the relative variant is the one you can expect to transfer.

```python
# scripts/run_simreal.py  (core; test windows are always real)
import numpy as np, pandas as pd
from sklearn.base import clone
from sklearn.metrics import f1_score
LAB = ["Empty", "Occupied", "Transition"]

def add_relative(df, rx=("R1", "R2")):
    df = df.copy()
    for run, g in df.groupby("run_id"):
        base = {r: g[g.label == "Empty"].sort_values("t_start")[f"{r}_mean"].head(20).median() for r in rx}
        for r in rx:
            for k in ("mean", "min", "max"):
                df.loc[g.index, f"{r}_{k}"] = g[f"{r}_{k}"] - base[r]
    return df

def fit_weighted(model, X, y, w):
    m = clone(model)
    key = (m.steps[-1][0] + "__sample_weight") if hasattr(m, "steps") else "sample_weight"
    try: return m.fit(X, y, **{key: w})
    except TypeError:                         # KNN / Threshold: no weights -> sub-sample by weight
        keep = np.random.default_rng(0).random(len(y)) < w
        return m.fit(X[keep], y[keep])

def regimes(model, name, Xr, yr, Xs, ys, w_sim):
    out = {"real": clone(model).fit(Xr, yr)}
    wt = np.r_[np.ones(len(yr)), np.full(len(ys), w_sim)]
    out["mixed"] = fit_weighted(model, np.vstack([Xr, Xs]), np.r_[yr, ys], wt)
    if name == "RandomForest":
        rf = clone(model).set_params(n_estimators=150, warm_start=True).fit(Xs, ys)
        out["pretrain_ft"] = rf.set_params(n_estimators=300).fit(Xr, yr)
    return out                                 # sim-only is trained once, outside this loop

def run(real, sim, cols, model, name, n_list, w_sim, reps=5, seed=0):
    rng = np.random.default_rng(seed)
    runs = real.run_id.unique(); store = {}
    Xs, ys = sim[cols].to_numpy(), sim.label.to_numpy()
    sim_only = clone(model).fit(Xs, ys)
    for held in runs:                                            # leave-one-REAL-session-out
        te = real[real.run_id == held]; Xt, yt = te[cols].to_numpy(), te.label.to_numpy()
        assert (te.origin == "real").all()
        store.setdefault(("sim", 0, 0), []).append((yt, sim_only.predict(Xt)))
        for n in n_list:
            for rep in range(reps):
                tr_runs = rng.choice([r for r in runs if r != held], size=min(n, len(runs) - 1), replace=False)
                tr = real[real.run_id.isin(tr_runs)]
                for reg, m in regimes(model, name, tr[cols].to_numpy(), tr.label.to_numpy(), Xs, ys, w_sim).items():
                    store.setdefault((reg, n, rep), []).append((yt, m.predict(Xt)))
    rows = []
    for (reg, n, rep), pairs in store.items():
        y = np.concatenate([a for a, _ in pairs]); p = np.concatenate([b for _, b in pairs])
        rows.append({"regime": reg, "n_real": n, "rep": rep, "macro_f1": f1_score(y, p, labels=LAB, average="macro", zero_division=0)})
    return pd.DataFrame(rows)
```

**Reading the result.** Plot macro-F1 against the number of real training sessions (1, 2, 4, 8, all), one line per regime, with the spread over `reps` random choices of training runs and a bootstrap CI over held-out runs for the points you quote (the `bootstrap_macro_f1` helper in Part 19). The proposal's hypothesis is that simulation pre-training helps most when real sessions are few, and may give no benefit if the simulated body effect is poorly fitted. ### Part 25 — viva questions (add 33–44)

33. **Why add a simulator when you have real data?** The real room gives a few sessions, one layout and one board set. NS2 gives many seeded, perfectly labelled runs and lets us vary receiver count, placement, sampling rate and load, at the cost of being a model whose fidelity we have to measure.
34. **Why NS2, not ns-3?** The project specifies NS2 for its 802.11 stack, Shadowing model, `setdest` mobility and NAM, and its documentation is stable. It is legacy software, so we pin the toolchain in a container; ns-3 is listed as future scope.
35. **What does NS2's Shadowing model do, and what does it miss?** Mean path loss with exponent β plus an independent Gaussian dB offset of spread σ per packet. It has no real multipath and no memory between packets, so simulated variance and autocorrelation differ from real RSSI.
36. **How is a person represented?** As a node whose position matters only to BodyShadow: if it is near the straight line between transmitter and receiver (scaled by the first Fresnel-zone radius), it adds excess loss and extra variance. Movement changes this packet by packet.
37. **How did you calibrate it, and how do you know you did not overfit?** Path-loss exponent, level and spread were fitted from dedicated empty-room distance runs; body loss and width from runs with a person at known offsets. Those runs (D0) are never test data, and fidelity is reported on separate sessions as well as in-sample.
38. **What do KS and Wasserstein tell you?** KS is the largest gap between two cumulative distributions (0 to 1); Wasserstein-1 is the average shift in dB needed to make them match. We report the statistics but not p-values, because overlapping windows are not independent.
39. **Why round simulated RSSI to integers?** The real chip reports whole dB, which adds about 0.29 dB of quantisation noise and changes the distributions' shape. Without matching it, fidelity metrics would penalise a difference that has nothing to do with the channel.
40. **Does simulated data help the classifier?** That is what E16 measures: sim-only, real-only, pre-train plus fine-tune and mixed, all on held-out real sessions, as a function of how many real sessions are available. State the measured outcome; the hypothesis was a benefit that shrinks as real data grows, and a null result is acceptable.
41. **Why can simulated windows never be in a test set?** The test set must represent deployment, which is the real room. A simulator that we calibrated and then test on would measure the simulator's agreement with itself.
42. **Why a network study if the prototype uses USB?** USB hides the radio network. E15 asks how many receivers, devices and what sampling rate a wireless collection design could sustain, which bounds the practical rate and the latency budget; it is not a statement about the prototype.
43. **What if the body model is wrong?** Then fidelity (E14) shows it, sim-assisted training may not help (E16), and the report says so. Headline claims never depend on the simulator.
44. **How do you make the NS2 results reproducible?** Pinned container, patches and Tcl in Git, seed and parameter block in every run's `meta.json`, container digest and calibration run list in the experiment registry.
